🤖 智能体与决策训练

MGOA 数据集 (Optimus-2)
CVPR 2025 工作，包含 8个原子任务的 25,000个视频，提供了约 3000万 个“目标-观察-动作”三元组，专门用于训练多模态 Minecraft 智能体的决策能力。

OmniJARVIS (NeurIPS 2024)
提出了统一的视觉-语言-动作（VLA）分词方法，将长期交互中的指令、记忆、观察和行为轨迹打包成统一 token 序列。数据集、模型和代码将在 craftjarvis.org/OmniJARVIS/ 发布。

Agent Society 蒸馏数据集
包含 1,355 条 SFT 样本，专门蒸馏了 Claude Sonnet 在 Minecraft 生存/社交沙盒中的逐 tick 决策，可直接用于微调小型本地模型。

MineRL-v0 / BEDD
MineRL-v0 包含人类演示数据。BEDD 在此基础上扩展，包含 2600万 图像-动作对（来自近 14,000 个视频），以及超过 3,000 组带自然语言解释的人类偏好评估，非常适合训练和评估处理“模糊任务”的智能体。

🧠 推理与指令微调

MineMA 指令数据集
包含 390,317 条指令条目，专为 Minecraft 问答任务设计，已用于微调 MineMA 系列模型（基于 LLaMA-3-8B/70B）。

Odyssey 技能数据集
在 Minecraft Wiki 基础上构建了超过 39万条指令条目的问答数据集，用于训练具备开放世界技能的智能体，所有数据、模型权重和代码均已公开。

CraftAssist 语义解析数据集
包含 7,000 条人类话语及其对应的语义解析，用于训练智能体理解指令驱动的通信。

🎬 多模态与行为克隆

PLAICraft (10,000+ 小时)
大规模、时间对齐的多模态数据集，同步记录了视频、游戏音频、麦克风输入、鼠标和键盘动作五种模态，精度达毫秒级。包含超过 10,000 小时的多人游戏数据，目前已公开 200 小时子集。

VPT (Video PreTraining) 数据集

MineDojo 互联网知识库
一个庞大的开放知识库，包含 73万+ YouTube 视频（带时间对齐文本）、6,000+ Wiki 页面和 34万+ Reddit 帖子，为智能体提供互联网规模的常识知识。

💻 代码与模组开发

Forge Coder v1.21.11

📊 思维链数据集

claude-opus-4.6-4.7-reasoning-8.7k
包含 8,706 条多领域英文样本，由 Claude Opus 4.6（53.7%）与 4.7（46.3%）生成。每条附带 150–500 词的长片段推理过程，覆盖代码、数学、科学、金融、法律等 28 个细分类别。采用 <think> 格式，Apache-2.0 许可。

OmniThought
ACL 2026 工作，200 万条 CoT 过程，由多个强力 LRM 生成并验证。每条标注了 Reasoning Verbosity (RV) 和 Cognitive Difficulty (CD) 两个新颖指标，用于刻画 CoT 的适当详细程度和认知难度。基于 Qwen2.5/3 验证了 RV 和 CD 评分对训练效果的正向影响。

CoT-Trace-Inverted-28K
28,391 条 CoT 推理样本，通过多源蒸馏和 Trace Inversion（轨迹反转） 构建。核心思路是从压缩的模型输出中重建完整的结构化推理链，让学生模型学习严谨的逐步推理而非模仿捷径结论。覆盖数学、科学、代码、逻辑等，统一 <think> 格式，按推理链长度全局排序，适合课程学习（短→长 CoT 渐进）。

Open-CoT-Reasoning-Mini
10,200 条蒸馏 CoT 推理样本，覆盖数学、医学、艺术、社科、计算机、逻辑谜题等领域。专为 10B 以下参数模型设计，每条包含 input（附带 “Let's think step by step:” 提示）和 output（含 <think> 和 <answer> 双标签）。Apache-2.0 许可。

TART (Textual Answers & Reasoning Traces)
约 344,294 条指令微调记录，由 9 个高保真数据集合成，融合了 Claude Opus 4.6、DeepSeek-V4、GPT-OSS 等前沿模型的推理轨迹。严格四列 Schema：question、reasoning（CoT 轨迹）、answer、source，兼容 Unsloth、HF TRL、Axolotl 等训练框架。Apache-2.0 / MIT 许可。

Dolci-Think-SFT-32B-Multilingual
大规模多语言长 CoT 推理语料，覆盖英、法、德、西、中、斯瓦希里六种语言。每种语言约 50 万条样本，序列长度可达 32,768 tokens。以数学（37.93%）和代码（34.80%）为主。ODC-BY 许可。

mCoT-MATH
大规模多语言数学 CoT 推理数据集，包含约 630 万条样本，覆盖 11 种语言。

💻 思维链蒸馏代码库

CODI（EMNLP 2025）
将思维链压缩到连续空间的自蒸馏方法。提供 CODI-gpt2 和 CODI-llama3.2-1b-Instruct 预训练权重，支持 GSM8K、SVAMP、GSM-Hard、Multi-Arith 等数学基准的评估。关键参数包括 num_latent（潜在思维数量）、distill_loss_type（l1/l2/smoothl1）等。

Reasoning-Skill (TRS)（ACL 2026 Oral）
“Thinking with Reasoning Skills”框架，将 CoT 轨迹蒸馏为可复用的技能卡片。四步流程：生成源 CoT 轨迹 → 蒸馏为技能卡片 → 检索相关技能 → 注入提示并运行 TRS 推理。提供完整可运行脚本（含 mock 模式，可离线运行）。

📄 综述与资源索引

A Survey on Large Reasoning Models with Self-Play Deep Reinforcement Learning and Chain-of-Thought（ACM, 2026.01）
系统综述自博弈深度强化学习驱动的 CoT 推理，涵盖树搜索规划、过程监督与奖励建模、自博弈与自我改进机制等关键技术。

Awesome Long-Chain-of-Thought Reasoning with Tools
长 CoT 推理与工具使用的研究资源和论文精选列表，包含 START（自学习推理器 + 工具集成）、Hint-RFT 等方法的论文和代码链接，有中英文版本。

CoT Distillation Collection (HuggingFace)
SLoonker 维护的 CoT 蒸馏数据集集合，收录了 GLM-5.1-Reasoning-1M、DeepSeek-V4-Distill-Combined-14000x、Kimi-K2.5-Reasoning-1M、GLM-5.2 系列（金融/科学/对话/逻辑谜题）等多个蒸馏数据集。

🚀 前沿大模型蒸馏成果

DeepSeek-R1 蒸馏系列
这是目前最主流、生态最完整的蒸馏成果之一，基于 80万条 R1 生成样本对多个开源模型进行 SFT 微调。包含 Qwen-1.5B/7B/14B/32B 和 Llama-8B/70B 共 6 个规格，权重在 HuggingFace 和 GitHub 开源，采用 MIT 许可。

Claude / GPT / Gemini 蒸馏模型
社区有项目将 Claude、GPT、Gemini 等前沿闭源模型的推理能力蒸馏到开源架构中。例如 Qwen3.5-9B-Claude-4.7 提供了 GGUF 量化版本，在消费级硬件上即可运行。另有 Nemotron-3-Super-120B 从 Claude-4.6 Opus 蒸馏而来，BF16 精度，总大小约 241 GB。

Progressive Distillation 项目
包含从 Qwen 0.5B 和 Gemma-3-270M 蒸馏的多个学生检查点，涵盖不同学习率和随机种子组合，适合对比蒸馏策略的效果。

DistillDetect
提供从 Llama-3.3-70B-Instruct 蒸馏到 Qwen2.5-3B 的复现成果，以及从 o1 蒸馏到 Gemma-3-4B 的版本，附带完整的模型权重和评估结果。

🧩 经典小模型蒸馏成果

DistilBERT
HuggingFace 上有完整的 DistilBERT 组织，包含从原始 BERT 检查点通过师生学习蒸馏得到的模型，参数比 BERT-base 减少约 40%，推理速度提升约 60%。

TinyBERT
华为诺亚方舟的经典工作，提供 4层-312维 和 6层-768维 两个规格，涵盖所有 GLUE 任务的蒸馏版本，权重已上传至 HuggingFace。

MiniLLM
微软的 LLM 蒸馏方法，提供从 OPT-13B 蒸馏到 1.3B、从 GPT2-xlarge (1.5B) 蒸馏到 120M/760M 的多个学生模型，使用反向 KL 散度进行蒸馏。

DistilGPT
基于 GPT-2 的蒸馏模型，提供 GGUF 量化格式，最小版本约 163M 参数，可在本地轻量运行。

🖼️ 多模态与专用蒸馏成果

Byrne-VLM-131M
一个仅 131M 参数的视觉语言模型，从更大的 VLM 蒸馏而来，权重文件仅 571 MB，包含完整的推理代码。

FlashWAM-RoboTwin
面向具身 AI 的蒸馏世界动作模型，将推理压缩到每个模态 单步，实现最高 23倍加速，完整模型（蒸馏 transformer + 编码器）已在 HuggingFace 发布。

NanoVDR-D
从 8B 视觉语言教师蒸馏出的 457M 编码器，将文档页面图像压缩为单个 4096维向量，权重以 float32 格式发布。

efficientSAM3
从 SAM3 蒸馏的轻量级分割模型系列，最小版本（EV-M）仅 89.2M 参数，比原版小 90%，提供 HuggingFace 权重下载。

这些成果都可以直接从 HuggingFace 或 GitHub 拉取，部分还附带了推理代码和量化版本。你目前是想找某个特定教师模型（如 DeepSeek、Claude）的蒸馏成果，还是更关注某个参数规模（如 1B 以下、3B 左右）的学生模型？为 OpenJev 这类决策模型扩展数据来源，电子书确实是很好的思路。它们能提供结构化的知识体系，比零散的网络文本更适合用来生成高质量的合成训练数据。以下按不同方向为你整理了一些可获取的电子书资源。

📚 决策理论与算法（核心方向）

这部分与 Jev 的“决策”本质最直接相关，能为模型提供决策框架和算法基础。

· 《Foundations of Computational Decision Analysis》：开放获取电子书，涵盖计算决策分析基础、多准则决策方法（如 SMART、AHP）及概率多准则决策，为构建决策模型提供理论基石。
· 《Algorithms for Decision Making》：MIT Press 出版，PDF 在 CC-BY-NC-ND 许可下共享。系统讲解不确定性下的决策算法，面向高年级本科生和研究生，实操性强。
· 《Markov Decision Processes and Reinforcement Learning》：Puterman 和 Chan 合著，前五章预印本可免费下载。深入讲解 MDP 的数学和算法基础，是理解序列决策的经典之作。
· 《Decision Modeling》：583 页免费 PDF，涵盖线性优化、敏感性分析等决策建模内容，适合工程和管理决策场景。

🧠 知识蒸馏与模型压缩（蒸馏技术参考）

这部分直接服务于你的蒸馏任务，提供方法论的直接参考。

🧰 通用蒸馏工具包

EasyDistill（阿里云，EMNLP 2025 Demo）
覆盖黑盒/白盒蒸馏的完整工具包，支持数据合成、SFT、排序优化、RL全流程，适配 System 1（快速直觉）和 System 2（慢速分析）两类模型。提供 DistilQwen 系列蒸馏模型和开源数据集，已集成到阿里云 PAI 平台。GitHub: modelscope/easydistill

DSKD（EMNLP 2024，交叉Tokenizer白盒蒸馏）
通用白盒蒸馏框架，同时支持同Tokenizer和跨Tokenizer的LLM蒸馏，已支持从72B模型蒸馏到1.5B模型（DeepSpeed ZeRO-3）。后续发布了DSKDv2，引入更好的投影器初始化和on-policy蒸馏。GitHub: songmzhang/DSKD

DistillFlow（多策略蒸馏 + 动态资源分配）
支持 logits、注意力、中间层三种蒸馏策略，具备多GPU动态资源分配能力，兼容 HuggingFace Transformers、PyTorch 和 DeepSpeed。配置示例中直接展示了 Qwen2-1.5B（学生）从 Qwen2-7B（教师）蒸馏的完整配置。GitHub: horus-ai-labs/DistillFlow

DistillKitPlus（离线蒸馏 + PEFT 友好）
专注于低资源场景的蒸馏工具包，支持预计算logits实现内存高效训练，集成LoRA微调和4-bit量化。支持KL散度、通用Logit蒸馏（ULD）和多级最优传输（Multi-OT）三种损失函数，覆盖同/跨Tokenizer场景。GitHub: agokrani/distillKitPlus

transformers_distillation / HF Distiller（HuggingFace 生态原生）
封装HuggingFace Trainer 的蒸馏库，可从Hub加载任意教师模型，从零创建自定义学生模型，支持自定义层数、注意力头数和嵌入维度。Quick Start中展示了从BERT-base蒸馏出4层小模型的完整代码。GitHub: Dhiraj309/transformers_distillation

🤖 具体模型蒸馏成果（含预训练权重）

DeepSeek-R1 蒸馏系列（6个规格，MIT 许可）
包含从DeepSeek-R1蒸馏的6个小模型：Qwen-1.5B/7B/14B/32B 和 Llama-8B/70B，基于80万条R1生成样本进行SFT微调。所有模型权重已在HuggingFace和GitHub开源。GitHub: deepseek-ai/DeepSeek-R1

PolyDistill / TinySage 系列（多教师黑盒蒸馏，0.6B-8B）
统一调度 GPT-4o、Claude、Gemini 作为教师模型，通过投票/加权/去噪策略融合多教师回答，蒸馏出TinySage系列（0.6B/1.7B/4B/8B）。支持logits蒸馏、特征层蒸馏、指令蒸馏、On-/Off-policy流程和LoRA/SFT微调，权重在ModelScope发布。GitHub: chensongpoixs/PolyDistill

Mimi-0.6B（消费级显卡全参数蒸馏，中文）
由Qwen3-4B在单张RTX 5090上全参数蒸馏得到的0.6B中文模型。训练脚本、数据集（alpaca_gpt4_zh）和教师模型配置全部开源，包含完整的踩坑记录。GitHub: aifeifei798/mimi_0.6b

Hybrid Policy Distillation (HPD)（ICML 2026，推理模型蒸馏）
面向推理模型的蒸馏框架，提供Qwen2.5-1.5B从Qwen2.5-7B-Thinking蒸馏的学生模型。在AIME24/25、AMC、MATH、OlympiadMath、GPQA等推理基准上提供了详细的师生对比数据，集成 LlamaFactory 和 verl 两种训练实现。GitHub: zwhong714/Hybrid-Policy-Distillation

Jasper & Stella 系列（嵌入模型蒸馏）
从SOTA嵌入模型蒸馏的轻量级双语（英/中）模型，Jasper-Token-Compression-600M在2025年11月发布，采用token压缩蒸馏方法。模型权重和数据在HuggingFace Hub发布。GitHub 项目：infgrad/jasper_en_vision_language_vl

🖼️ 多模态蒸馏成果

LLaVA-KD（多模态大模型蒸馏框架）
提出 Multimodal Distillation（MDist） 和 Relation Distillation（RDist） 两种策略，配合三阶段训练（蒸馏预训练→SFT→蒸馏微调），在不改变模型架构的前提下显著提升小规模MLLM性能。GitHub: Fantasyele/LLaVA-KD

Align-TI（ICML 2026，Token交互蒸馏）
通过动态token交互而非静态next-token对齐来蒸馏多模态大模型，蒸馏出的 Align-TI-1B 基于LlamaQwen2构建，在HuggingFace发布权重。GitHub: lchen1019/Align-TI

DHO（视觉语言模型半监督蒸馏，含预训练检查点）
从CLIP等VLM蒸馏到小模型，在仅1%和10%标注数据下达到SOTA。提供4个预训练检查点（ViT-B/16 和 ViT-L/14，1%和10%标注），Top-1准确率最高85.9%，参数量86M-304M。HuggingFace: erjui/dho

SigLino（CVPR 2026，视觉基础模型蒸馏）
从 DINOv3 和 SigLIP2 蒸馏的视觉编码器集合，支持多分辨率理解。提供5个预训练检查点（30M/70M/0.6B密集版，以及MoE版本），全部可直接下载。GitHub: tiiuae/siglino

Multi-Level-OT（AAAI 2025 Oral，跨Tokenizer蒸馏）
使用多级最优传输实现跨Tokenizer的通用知识蒸馏，支持Llama2-7B、Llama-3-8B、Mistral-7B、Qwen-7B等教师模型蒸馏到Pythia-160M、OPT-350M等小模型，提供所有学生模型的检查点下载。GitHub: 2018cx/Multi-Level-OT

🌍 垂直领域蒸馏

OpusDistillery（多语言NMT蒸馏，Helsinki-NLP）
面向多语言神经机器翻译的端到端蒸馏流水线，集成OPUS-MT和HuggingFace开放教师模型，支持多语言场景和GPU利用率追踪。GitHub: Helsinki-NLP/OpusDistillery

deepseek-r1-distilled-c（轻量级R1蒸馏实现）
包含6个从DeepSeek-R1蒸馏的小模型的最小实现，代码简洁（仅SFT），适合快速理解和复现R1蒸馏流程。GitHub: Rmcrow/deepseek-r1-distilled-c

这些仓库中，EasyDistill、DSKD、DistillFlow、DistillKitPlus 是通用框架，适合你根据自己的教师/学生模型组合来使用；DeepSeek-R1蒸馏系列、PolyDistill/TinySage、Mimi-0.6B、HPD 提供了已训练好的权重，可以直接下载使用或在此基础上继续微调；LLaVA-KD、Align-TI、DHO、SigLino 则聚焦多模态场景。你目前更想直接用现成的蒸馏权重，还是基于某个框架来训练自己的学生模型？为你整理了一批可以直接阅读的资料，涵盖系统教程、实战博客、综述论文和书籍，方便你随时翻阅。

· Common Corpus：一个庞大的多语言公共领域语料库，包含200万至300万本书籍和报纸，规模巨大，适合需要海量数据的预训练任务。
· Project Gutenberg：最经典的免费电子书库，包含超过 7万本文学著作，涵盖小说、散文、诗歌、历史、科学等。衍生数据集（如PG-19）常被用于长文本训练。
· Books3：包含约 19.7万本全长书籍，混合了受版权保护和公共领域的作品，在多个大型语言模型的训练中被广泛使用。

📖 学术与专题书籍语料库

除了通用书籍，针对性的学术或专题语料能帮助模型在特定领域建立更精准的认知。

· Academic Textbook Corpora：一个包含 3.9万本教科书、覆盖 5000多个学科和 15种语言的语料库，专为多语言知识建模设计。
· Children's Book Test (CBT)：基于Project Gutenberg的一百多本儿童读物构建，适合训练基础的语言理解和常识推理。

🌐 多语言与特定领域数据集

为了构建更全面的世界观，多语言和文化视角的数据同样重要。

· OWL (World Literature)：包含 20本书籍在 10种语言中的 3.15万个对齐摘录，适合研究跨语言知识回忆。
· EvolvingWorld：从 57本书籍中构建，包含 13.8万个监督训练样本，专门用于训练智能体理解复杂文学世界中的规则和状态更新。

💡 使用建议

· 数据配比：根据实践经验，严肃书籍、教材等高质量数据在训练中通常需要进行3-5倍的过采样，以更有效地构建模型的“智商”和推理能力。
· 关注版权：使用Books3等混合版权作品的数据集时需注意合规风险。优先选择Institutional Books 1.0、Project Gutenberg等公共领域资源更为稳妥。

🌍 世界模型与仿真框架

这类项目旨在让模型通过模拟环境来学习和理解世界动态。

· EvolvingWorld：一个开放模式框架，用于模拟交互式文学世界。它通过让角色扮演智能体与世界模型协同进化，训练智能体理解复杂世界中的规则和状态更新。项目基于57本书构建了138,596个监督训练样本。

· LingBot-World 2.0：蚂蚁灵波科技开源的世界模型系列，包括1.3B、14B等多个版本，基于视频生成技术构建世界模拟器。

· WKM (World Knowledge Model)：一个参数化的世界知识模型，旨在通过提供全局先验知识和动态状态知识，来促进智能体的规划能力。

📚 知识图谱与常识库

· CSKG (CommonSense Knowledge Graph)：一个综合性的常识知识图谱，整合了Wikidata、WordNet、FrameNet等多个来源，为常识推理研究提供支持。
· ConceptNet：由MIT媒体实验室开发的免费常识知识库，旨在为计算机提供其应该已经知道的广泛常识知识。
· FactNet：一个十亿级规模的多语言知识图谱，统一了17亿条原子断言和30.1亿个可审计的证据指针，源自316个维基百科版本。
· NovaCOMET：一个开放的常识知识模型，结合了知识模型和通用任务模型的优势，并通过符号知识蒸馏技术进行训练。
· Theogony：一个开放、民主的“世界大脑”项目，旨在构建AI背后的共享知识层，作为一个开放的公共资源，由所有人共同拥有和检查。

🛒 电商运营决策

长程仿真基准

· MerchantBench (arXiv:2607.28956)：365天 订单级电商运营仿真环境，基于 98,843 条真实电商产品记录，配备 26种 工具供 Agent 交互。覆盖产品采购、定价控制、现金流管理和混合延迟反馈适应，评估 8 个 LLM 在 48 次 365 天运行中的长期决策连贯性。最佳 LLM 仅达到人类参与者平均净资产的 27.3%。代码在 KhanCold/merchantbench。
· E-Commerce Bench (arXiv:2608.30730)：一年期 电商基准，LLM Agent 并发运行多个在线商店，进行市场研究、供应商谈判、库存采购、销售优化和退货处理。GPT-5.6 Sol 将初始 100,000 股本增长到 1,431,425，但欺诈防范排名第 16。代码在 QwenLM/E-CommerceBench。

💡 如何系统性地提升决策能力

1. 从“推理链”入手：优先使用claude-opus-4.6-4.7-reasoning-8.7k或Game Reasoning CoT，让模型学会“先思考，再决策”。
2. 引入“交互式学习”：利用Orak或DeliveryGym等RL环境，让模型在试错中优化决策策略。
3. 针对“多模态”场景：使用EQA-Decision或OmniDrive，训练模型在视觉输入下做出判断。
4. 构建“评估闭环”：通过BusinessCaseBench或C-SUITEBENCH定期评估模型的决策质量，指引迭代方向。
5. 结合你的具体场景：将上述通用能力与你之前关注的电商、客服、游戏、烹饪等领域数据结合，进行领域自适应微调。

优先使用 Awesome-LLM-RL 作为总索引，选取 Good Thinking Corpus（通用逻辑）、Orak（游戏决策）和 SpireEval（策略决策）三个数据集，构建覆盖“逻辑推理 → 交互决策 → 战略规划”的基础决策训练集。

阶段二：领域能力注入

从电商（CASCADE）、客服（CSConv、CCSE-CS、BANKING77）、烹饪（RecipeLLM） 中选取你最需要的2-3个领域，每个领域选取1-2个数据集进行混合。注意BANKING77和CCSE-CS同时覆盖银行和电商场景，可以一次获取两个领域的能力。

阶段三：多模态与推理增强

· 用 LongPerceptualThoughts 或 Math-CoT-20k 强化长链推理能力。
· 用 DriveLMM-o1 或 WOMD-Reasoning 注入多模态场景下的决策推理。
· 如需世界知识 grounding，引入 Cosmopedia 的合成教科书数据。

阶段四：世界模型与蒸馏优化

· 用 GigaWorld-1 或 stable-worldmodel 搭建世界模型训练环境，让模型在模拟环境中学习长期决策。
· 用 EasyDistill 工具包完成最终的蒸馏流程，支持黑盒/白盒两种模式。
· 多语言需求用 CUTE 或 LLM-Ko-Datasets 补充。

关键注意事项

1. 数据配比：高质量决策数据（如CoT推理链）通常需要3-5倍过采样，才能有效“激活”模型的推理能力。
2. 格式统一：所有数据集最终统一为 prompt + response + 可选 reasoning 的三元组格式，便于混合训练。
3. 评估闭环：用 GAMEBoT 或 Game Reasoning Arena 定期评估决策质量，指引下一轮数据迭代方向。

🏋️ 训练阶段干预

1. 数据侧：过滤与重加权

· NOVA 框架（ACL 2025）：通过内部一致性探测（ICP）和语义等价识别（SEI），筛除模型“不熟悉”的指令数据，从数据源头减少幻觉诱因。
· 选择性重加权（PNAS 2026）：仅重复 5% 的训练样本，就能将幻觉率降低高达 40%，且不牺牲准确率。这挑战了“训练数据必须去重”的常规做法，核心思路是刻意注入轻度校准偏差来抑制稀有事实的过度泛化。
· 选择性弃权学习（Seal）（ACL 2025）：在 SFT 阶段引入特殊 [REJ] token，让模型学会拒绝回答与参数知识不对齐的问题，从源头抑制“不懂装懂”。

2. 架构侧：解码层干预

· DeLask（IEEE 2026）：发现幻觉倾向于从更深层的解码器层产生。DeLask 动态跳过这些“问题层”，并将它们的隐藏状态与前层部分聚合，在保留连贯性的同时抑制错误信号。

🧠 推理阶段干预

1. 检索增强生成（RAG）

· GuarantRAG：显式解耦“推理”与“证据整合”，先用参数知识生成“内部答案”，再强制模型以检索文档为正样本、内部答案为负约束，抑制内部幻觉。在五个 QA 基准上准确率提升高达 12.1%，幻觉降低 16.3%。
· RE-IAG（ACM 2026）：将推理与证据组织成对齐的图结构，仅在内部推理停滞时才触发检索，把检索从“被动增强”转为“主动约束”，减少错误累积。

2. 解码策略

· 对比解码（Contrastive Decoding）：通过最大化“专家模型”与“业余模型”的输出差异，惩罚那些通用但可能错误的 token，保留事实性更强的续写。
· ActLCD（Active Layer-Contrastive Decoding）：将解码建模为序贯决策问题，用强化学习策略动态决定何时应用对比层，在五个基准上超越 SOTA。

3. 提示工程与自验证

· 组合策略：一项研究系统比较了 CoT + RAG + 自洽性 + 自验证 的组合效果，发现多策略叠加能显著降低幻觉并保持推理深度。
· 基于提示工程的框架（IEEE 2026）：结合动态阈值、交叉验证、自验证、CoT 和 RAG，在 Claude 3.7 和 DeepSeek-V3 上实现 2.23%–4.94% 的准确率提升，F1 提升约 7.09%，尤其对事实性幻觉效果显著。

4. 知识图谱约束

· 图约束推理（GCR）：通过 KG-Trie（基于 trie 的知识图谱路径索引）在解码时约束生成，确保推理严格遵循知识图谱的结构，消除无根据的推理路径。

📊 评估与检测

1. 公开基准

基准 规模 关注点
TruthfulQA 817 题/38 类 专门设计来诱发常见错误观念，但需注意榜单过拟合问题
HaluEval 35,000 样本 综合幻觉评测，含 QA、对话、摘要三类
HaluBench 15,000 样本 多 LLM 基准，采用任务感知的评估指标对齐策略
C-FAITH 60,702 条目 中文细粒度幻觉评估基准，基于 1,399 份知识文档构建

2. 检测方法

检测方法可分为三大类：基于反向验证（语法/逻辑设计复杂，易产生误差）、基于内部知识（依赖模型自身推理能力，自动化程度高）、基于外部数据库（准确性高但受资源限制）。

🛠️ 工程落地建议

1. 分层防御：没有单一技术能消灭幻觉。建议在数据层（NOVA 过滤）+ 训练层（选择性重加权）+ 推理层（RAG + 自验证）+ 解码层（对比解码） 各部署一道防线。
2. 区分幻觉类型：事实性幻觉（编造人物、API）主要靠 RAG 和后处理校验；忠实性幻觉（指令遵循失败、摘要不一致）靠 Prompt 约束和 SFT 能压住一截。
3. 持续评估：用 HaluEval 或 C-FAITH（中文场景）定期量化幻觉率，指引数据迭代方向。
4. 人机协同兜底：在医疗、法律等高风险场景，HITL（Human-in-the-Loop）策略可实现高达 95% 的幻觉降低，但需权衡可扩展性。

结合你正在做的 OpenJev 蒸馏，如果优先考虑低成本快速见效，建议从 选择性重加权（训练数据层） 和 GuarantRAG（推理层） 入手；如果追求可证明的可靠性保证，E³-Guarded Generation 框架提供了证据接地、逻辑蕴含和执行验证三层原则，并有形式化保证。

from datasets import load_dataset
ds = load_dataset("carosh/cli-1m", revision="v1.0", split="train")
zsh_ds = ds.filter(lambda x: x["shell"] == "zsh")

TraceEval（执行验证的多语言语义推理）
包含 10,583 个真实程序（2,129 测试 / 8,454 训练），从 1,600+ 开源仓库中提取，覆盖 Python、JavaScript、Java 三种语言。核心任务是让模型从源代码中恢复程序的运行时调用结构，每个正例边都由执行验证机械见证，消除了标注噪声。在训练集上微调 Qwen2.5-Coder 系列，F1 最高提升 72.9%，32B 版本达到 +55.6 F1，接近 Claude-Opus-4.6 零样本水平。仓库：yikun-li/TraceEval。

CodeSense（真实世界细粒度语义推理）
ICLR 2026 工作，从 Python、C、Java 真实仓库中收集项目，执行测试并采集执行轨迹，构建了面向细粒度语义推理任务的 ground truth 数据集。相比合成数据集和教学编程题，CodeSense 直接针对真实软件工程场景中的代码理解，同时开源了执行追踪框架和工具集，可以方便地为新仓库构建 ground truth。项目页面：codesense-bench.github.io。

SWE-QA（多跳代码理解）
LREC 2026 工作，包含 9,072 道多项选择题，从 12 个 SWE-bench Python 仓库中系统生成。题目设计了两种核心推理模式：Declaration-and-Call（将实体定义链接到使用位置）和 Interacting-Entity（考察多个协作组件间的动态关系）。生成过程结合了基于解析的实体提取和 LLM 辅助的出题，并精心验证了干扰项，确保区分真正的理解与表面模式匹配。15 个模型评估中，最佳准确率仅 74.41%，说明多跳推理仍是显著瓶颈。

SWE-ZERO / SWE-HERO（分阶段语义微调）
NVIDIA 发布的两阶段 SFT 配方，从 Qwen3-Coder-480B 蒸馏轨迹。SWE-ZERO 包含 30 万条无执行环境的轨迹，专门让模型掌握代码语义和仓库级推理；SWE-HERO 包含 1.3 万条基于执行的精炼轨迹，将语义直觉转化为严格的工程工作流。SWE-HERO-32B 在 SWE-bench Verified 上达到 62.2% 的解决率，且仅用 Python 训练就在 SWE-bench Multilingual 上取得 44.1% 的零样本迁移表现。数据集：nvidia/SWE-Zero2Hero。

OPEN-SWE-TRACES（多语言双模式蒸馏）
包含 207,489 条智能体轨迹，覆盖 Python、Go、TS、JS、Rust、Java、PHP、C、C++ 九种语言，来源于 20,000 个真实 PR。采用混合推理合成策略：Minimax-M2.5 生成带显式“思考”过程的轨迹，Qwen3.5-122B 提供高质量“非思考”轨迹。在 Qwen3-30B 系列上微调后，最佳模型在 SWE-bench Multilingual 上达到 57.1% 的解决率。

CodeEvo（交互驱动的代码语义合成）
ACL 2026 工作，采用双 Agent 架构：Coder 负责迭代式解决方案合成，Reviewer 负责编排生成轨迹。通过 Schema 系统性地架构逻辑和复杂度，结合确定性编译器反馈与语义评估的混合验证协议，构建了 CodeEvo-100K 大规模指令-代码对数据集，带有分级难度。仓库：QiushiSun/CodeEvo。

主要技术途径

动态扩展主要沿着宽度和深度两个维度进行，通常通过以下核心机制实现：

· 专家增殖 (Expert Upcycling)：通过复制现有专家并扩展路由器来增加专家数量（宽度）。复制提供“热初始化”，继承已学知识，随后通过训练打破对称性，驱动新专家特化。为防止完全对称，通常给复制专家参数添加微小高斯噪声，鼓励功能分化。
· 渐进式训练框架 (如 EMO)：将MoE容量视为可扩展内存，在训练中逐步增加专家池。EMO框架根据稀疏度缩放定律推导各阶段最优Token预算，匹配固定专家性能的同时提升实际训练效率。
· 专家融合与模块化增长：Branch-Train-Stitch (BTS) 等方法可独立训练专家，再以低成本拼接融合。正交增长策略则证明深度（层复制）和宽度（专家复制）增长相互独立，可自由组合，从17B扩展至70B仍能优于从头训练。

关键注意事项

· 计算预算的协同增长：这是最关键的一点。仅增加专家总数而保持激活专家数（top-k）不变，不会带来性能提升。必须按比例增加激活专家数，让Token被路由到新容量，才能有效利用新增参数。
· 训练稳定性与路由漂移：新增专家可能导致路由器重新分配旧样本，造成遗忘。解决方案包括：冻结现有专家或路由器以保护旧知识，或采用稳定路由、自适应冻结机制限制破坏性更新。
· 内存与通信瓶颈：专家总数增加会使全对全通信、优化器状态内存和分布式训练开销显著增长。实际训练耗时可能大幅增加，即使理论FLOPs不变。

总结与建议

对于你正在训练的开源MoE模型，动态增加参数量是高度可行且推荐的。建议从增加专家数量（宽度扩展） 入手，采用专家复制加微扰的热启动策略，并同步提高top-k值。同时需监控路由负载均衡，并准备好应对内存和通信开销的增长。

🎯 可移植的核心配置点

1. YaRN RoPE 缩放参数（必须移植）
这是长上下文扩展的基石。NeMo 配方中使用的是 factor=3.2（128K/40K）。移植到 HF 生态时，在模型 config 中设置：

```python

    "yarn_beta_slow": 1.0
}
```

其中 yarn_beta_fast=32.0 和 yarn_beta_slow=1.0 是 NeMo 配方验证过的稳定值。

2. 长上下文训练稳定性配置（建议移植）
NeMo 配方中特别强调了几个稳定性开关：cross_entropy_loss_fusion=False、calculate_per_token_loss=True、ddp.average_in_collective=False、use_distributed_optimizer=False。在 HF Trainer 中，前两个可通过自定义 loss 函数或 Trainer 参数间接实现；后两个与 Megatron 的分布式优化器相关，在 T4×2 的 DDP 环境下不直接适用，但 cross_entropy_loss_fusion=False 的思路（即不使用融合的 CE loss）值得在自定义 loss 时保留，以避免长序列下的数值不稳定。

3. 数据配置（必须移植）
NeMo 配方使用的是 nvidia/Nemotron-Cascade-2-SFT-Data 的 math 子集，前 10000 条样本，序列长度中位数约 12K，p95 约 57K，>40K 的样本占 11%。这个数据分布对长上下文训练很关键——需要在你的 SFT 数据中确保有足够比例的 32K-128K 长样本，否则模型学不到长距离依赖。

⚙️ T4×2 上的适配调整

· 序列长度：T4 单卡 16GB 显存，2 卡共 32GB。128K 全参 SFT 不现实，建议先用 LoRA/QLoRA 在 32K-64K 上做实验。有社区实践显示 Qwen3-0.6B 的 LoRA 微调在单卡上即可运行。
· 并行策略：放弃 NeMo 的 8 卡 CP，改用 DDP + 梯度累积。通过 gradient_accumulation_steps 来模拟大 batch，同时用 max_seq_length=32768 或 65536 控制单样本长度。
· 精度：T4 不支持 bf16，只能用 fp16，需注意 loss scaling。有 Kaggle 上的 Qwen3-0.6B 微调实践使用了 fp16 混合精度。
· 参考脚本：Unsloth 的 Qwen3-0.6B 微调 notebook 是 T4×2 上可直接运行的起点，你可以在它的基础上注入 YaRN 配置和长样本数据。

三个可移植点中，YaRN 参数和数据配置是必须移植的，稳定性配置中的 cross_entropy_loss_fusion=False 思路可保留，但 Megatron 专属的分布式优化器配置直接丢弃即可。在 T4×2 上，建议以 LoRA + 32K/64K 序列长度作为第一步验证，确认 YaRN 配置生效、长样本能被正常训练后，再考虑逐步扩展。
